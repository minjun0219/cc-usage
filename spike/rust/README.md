# spike/rust — 핫패스 Rust 이식 비교

**결론: 이식하지 않는다.** 근거는 아래 수치다. Rust 가 다시 후보로 떠오르면 여기서부터 시작한다.

## 무엇인가

`statusline` 핫패스만 Rust 로 다시 짠 것이다 — 설정 읽기 → stdin JSON 파싱 → `state.json`·`usage.json` 읽기 → 한도 병합 → 경보 판단 → `state.json` 원자적 쓰기 → 렌더.

`git status` 와 `extra_commands` 는 뺐다. 언어와 무관한 남의 프로세스라 비교에 잡음만 된다.

## 다시 재기

```sh
sh spike/rust/bench.sh
```

출력이 바이트 단위로 같은지 먼저 확인하고 다르면 멈춘다. **다른 일을 하는 두 프로그램의 시간을 비교하는 것은 의미가 없다.**

## 결과

| | Go | Rust |
|---|---|---|
| 핫패스 | 5.99 ms | **3.27 ms** |
| 바이너리 | 8.42 MB | **0.42 MB** |
| 외부 의존성 | **0** | 2 (serde·serde_json → 전이 포함 11) |

핫패스만 보면 Rust 가 절반 이하다. 전체 렌더(23.1 ms)로 환산하면 **-2.7 ms, 약 12%** — `git`(7.2 ms)과 extra 2개(18.9 ms)는 그대로이기 때문이다.

## 그런데도 이식하지 않는 이유

- 초당 2회 기준 5.4 ms/초, **0.5% CPU** 절약이다. 대가는 1,968줄 + 테스트 37개 재작성이고 그 과정에서 새 결함이 들어온다. 오늘 리뷰에서 나온 다섯 건이 그런 종류였다.
- Rust 표준 라이브러리에 **JSON 도 타임존도 없다.** `serde` 를 들이는 순간 "외부 의존성 추가 금지"가 깨지고, 타임존은 여기서 TZif 파서를 직접 써야 했다 (`local_offset`).

## 다시 볼 조건

**`git`·`extra_commands` 를 캐싱 층으로 빼서 렌더가 핫패스만 남을 때.** 그러면 5.99 → 3.27 ms 가 전체의 45% 절감이 된다. 지금은 전체의 12% 다.

## 밟은 함정

처음 측정에서 Rust 가 **9.08 ms 로 Go 보다 느리게** 나왔다. 언어 차이가 아니라 이쪽만 `sync_all()`(fsync)을 하고 있었기 때문이다. Go 의 `store.Write` 는 fsync 하지 않는다. 빼자 3.27 ms 가 됐다.

비교할 때는 **양쪽이 정말 같은 일을 하는지** 부터 본다. 한쪽에만 있는 syscall 하나가 결론을 뒤집는다.
